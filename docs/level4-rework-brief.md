# 第四关重做：第一次回返（2026-10-30）

本文件取代旧设计中的值班室、电路箱、辨风出口与最终结算。第一轮（2026-10-30）只做到第一次列车异变及车内探索；2026-11-14 用户已授权续作，本轮（第二轮）加入「第二次回返 + 操作痕迹保留 + 延迟脚步声」，并落下阶段定义与每轮目标的基础结构。更远的第三、四轮与破局仍未定，代码里只用有限阶段配置预留位置，不预先写死剧情。

## 本次可玩流程

1. 承接第三关故障停车。玩家在正常地铁内，以 E 打开步道侧中门，真实下车。隧道深处几乎全黑，只有车门残存的应急光能看清近处步道。
2. 在门外检修步道发现一只实体旧手电（靠近门口、细弱定位灯，不能埋在地里）。E 拾取后手电可用，F 开关，拥有本关独立电量。未拾取时 F 不能凭空照明。
3. 顺着同一条宽敞侧向检修步道一直向前。没有需要进入的墙内房间、侧门谜题或分叉任务。电缆、排水沟、环形衬砌与轨道扣件提供真实工业细节。
4. 玩家持续前进，无缝经过同方向空间接缝。保持走路速度、镜头朝向、眼高、侧向偏移；没有黑屏、淡出、强行转向、冻结、弹窗或可见死巷。穿缝时前后可见的隧道与灯光应一致，列车必须仍在手电有效距离/雾遮挡之外，走近才看见起点和列车。支持反向穿缝、横移和回头，不能抖动或每帧反复加圈。
5. 第一次真正前进穿缝触发一次异变：原先较新的列车已经老旧、锈蚀、畸形。预建两个版本，统一渲染层和灯池；列车变化发生在不可见位置，绝不在玩家眼前换模。异变保留一条可实际进入的中门和宽敞车内过道。
6. 玩家重新进入列车探索，发现一组备用手电电池以及一枚「应急通行钥匙」（作为后续通关道具，具体用途留待用户决定）。拾取有实体模型、近距离可见交互、一次性反馈与清晰物品状态。
7. 两种物品都拿到后仅显示“收好电池和钥匙，继续探索”一类轻提示，继续自由探索。本次没有通关、终章、出口解谜或结算，不写历史最佳纪录。

## Codex 美术方向与资产接口

- 风格是被遗弃的地铁现实主义：冷灰、近黑、克制的暖白手电与一点黯淡琥珀应急灯。禁用赛博霓虹、满墙鲜红、过量绿 EXIT 发光板、全景泛白照明。
- 黑暗必须有层次：不开灯只能辨近处脚下和列车轮廓；开灯能读出约 10–15m 的墙体、管线、轨道和物品。手电光束稳定，边缘柔和，不使用每帧大幅闪烁或频闪。
- `levels/level4-art.js` 为 Codex 美术配置与材质工厂；DSH 只消费接口，不重画贴图、不重写色板。接缝两端的重复细节与 UV 米制周期一致，衬砌和线缆不能穿出接缝。
- 贴图是微表面，不是把高光烘死的照片。混凝土可见毛孔、细裂与竖向渗水；旧车漆面有灰绿白底、斑驳锈蚀与油污；座椅有暗青乙烯基细纹和局部磨损。粗糙度占主导，局部水光适度。
- 异变必须同时具备材质与几何证据：车体板材轻微鼓曲、窗框错位、部分扶手倾斜、车顶局部下垂。使用受控变形，不堆砌相交方块。可走净高 >=2.15m、门净宽 >=1.1m、中心过道净宽 >=1.0m；碰撞与变形后的实际网格匹配。
- 资源可读但不发光描边：电池放在敞开的座椅旁应急收纳架中，钥匙置于可接近的驾驶端设备托盘上。车内暖色小灯引导，避免物品漂浮/埋墙/不可达。
- 不加入追逐敌人、强制尖叫或直白解释鬼打墙的计数 UI。

## DSH 程序范围与自测

保持 `createLevel4(ctx)`、独立 `L4_LEVEL=3`、`TUNNEL_LAYER=3`、`L4_OX` 与主引擎融合方式。允许重构关卡模块、宿主 L4 专用输入/状态/场景、检查页及测试；不要修改 L0/L3 原玩法。`colliders`、`bounds` 若被 ACTIVE_* 引用，动态变化须原地更新或正确重绑定。单次实例预建/预热所有版本，回环/拾取不创建新灯或编译新 shader。

手电的 owned/on/charge、电池存量和钥匙状态要有唯一来源。初始电量足够正常探索至少一次回环及异常列车；电池主动消耗并支持更换（E 拾取备用、R 沿用重开，不改为装电池）。建议拾电池时即补充电量并保留一节备用，低电量时 F 长按/另键不得引入未说明操作；实现采用最简单的自动补给并明确 HUD。电量耗尽后保留可寻找电池的局部应急光，不能永久卡关。

暂停、失去指针锁、记录卡或切关时不得消耗电量或推进回环。R 完整重开，反复进出关不积累物件/音频/监听器。第三关两条选择都进入新版，URL/启动器第4关入口可用，本地/CDN HTML同步。改写旧结算用例为“阶段完成不结算、不写档”；不要保留失效的 T17/柜子/时钟机位调用。

必须运行真实 THREE、真实主引擎/模块测试：物品拾取距离与遮挡；未持有不可开手电；电耗/补给/暂停/R；正常下车与异变列车可实际进出；至少多轮正逆方向及贴墙穿缝；朝向/相机/速度连续；一次异变与资源不刷新复制；网格/灯数稳定；不写档；L3回归；本地/CDN同步与入口。若浏览器/GPU可用再检查控制台和代表画面，不能把 Node 桩称为浏览器验证。有错误先自行诊断修复，最终报告具体命令、真实结果和剩余限制，Codex复核后验收。

禁止 git reset/clean/commit/push，禁止改 DSH 配置/认证/权限/网络，不触碰无关目录。

## 第二轮：第二次回返 + 操作痕迹 + 延迟脚步（2026-11-14）

前一节的"本次到此、不补后续剧情"是第一轮的范围界定；本轮已获用户授权续作，因此第四节流程的第 4–7 条之外新增下面这一段，其余（手电、车内外尺度、材质、不结算不写档）全部保持有效。

### 新增可玩流程（接在第一次回返之后）

1. 取到应急钥匙后，步道左墙出现一樘真实开洞的检修门（净宽 1.16m、净高 2.20m，位于 6m 模数 z=-6（两接缝正中，离两端各 42m），回返落点距房体最近处仍约 40m，远在手电 19m 射程与雾的可读范围之外）。E 第一次用钥匙解锁，之后可自由开关。
2. 门内是一间 2.9×2.9m 的侧向维修间：混凝土墙、旧瓷砖背墙、门侧应急灯箱、后墙配电箱（锈蚀门板、三只仪表、可反复扳动的拉杆、供电状态灯）。E 扳动拉杆可反复通断电，首次送电记为"已完成送电"这一单次事实。
3. 送电后房灯亮起、设备运转声持续；目标切换为"沿亮起的应急灯查看隧道"。
4. 玩家走出维修间、继续沿步道前进并**正向**跨过空间接缝时推进一次第二次回返：整节老车厢换成一节完整的、可进入可走动的列车——外壳仍是锈蚀旧板，但所有车窗都透出同一片整洁灰绿内饰、冷白偏绿灯带与整排吊环。远处先见窗内微光，走近并真正进车顺着车长看过去，才确认"进入车厢检查变化"。
5. 第二次回返期间，玩家自己的真实落脚会带出 0.62–0.92s 后的远处回声脚步（每次落脚踏一组、最多两次余步、软音量/远距离衰减、声源偏向侧后远处）；站定、撞墙、腾空、暂停、失焦都不会凭空产生。
6. 维修间的门开合状态与电闸通断状态在正/反向穿缝、离关重进之后都按玩家最后一次的真实操作保留，作为可验证痕迹；R 重开完整清回初始。

### 实现要点（DSH）

- 平面与尺寸常量集中在 `levels/level4-tunnel.js` 的 `ROOM`（`cz=-6.0`、`gapHalf=0.60`、`gapZ1=-6.60`、`gapZ2=-5.40`、`doorH=2.20`、`depth=1.45`（`z1/z2` 由它派生）、`x1=-7.10`、`ceilH=2.55`、`wall=0.22`；`breaker`/`lamp` 的 z 也由 `cz` 派生）。门洞、过梁、门槛、门套、地面与 `groundAt`/`ceilingRaw`/`colliders`/`bounds`/互动点/取证机位全部由这一份数据派生，禁止贴假门或穿墙交互，也不留硬编码的旧 z。
- 步道左墙在房间 z 段以外改为"从 `ROOM.x1` 到 `WALK_X1` 的实心土层块"碰撞（而不是薄墙皮），保证被击退或瞬移时推出方向仍是回到步道；房间 z 段内只保留洞口两侧墙皮，门洞由 `maintDoor` 屏障在关门时挡住（`y1=900` 表示不挡）。
- 阶段推进、物件状态、物理穿缝计数三者分开：阶段表 `FLOW`（`approach → salvage → unlock → enter → power → return2 → witness`，另有 `beyond`）由"已完成事实"单调推进，目标文案与局部异常都从阶段派生；`seamState.forward/back/crossings` 只负责物理穿缝计数，误关电闸不会回退阶段。
- 第二次回返资格 `secondReturnReady() = unlocked && entered && powerDone`；只在**正向**跨缝且尚未推进时触发一次，反向/抖动不刷。
- 延迟脚步：宿主在真实落脚点（`player.grounded` 且 `stepTimer` 归零、常规脚步声已播之后）向 `l4.onFootstep({x,y,z,grounded})` 通知；模块用实际位移过滤（`minMove=0.25m`）、队列上限 2、延时 0.62–0.92s、播完计数，暂停/离关/R 清空队列并调用 `ctx.onEchoCancel()` 停掉已排入的 WebAudio 源。回声本身是一组**同步**足音（音频层不再自己叠加 0.16/0.62s 二次延时），避免"2 个队列事件变 4 拨声"。
- 第二次回返是**整车替换**（2026-11-14 返工）：`buildSecondCar()` 预建第三套车体（`visible=false`，不叠放旧车组），与正常/老化车体共用同一套窗洞数据（`stationPlan`/`CAR_WIN_OUT`）和建造工具，只按材质合并成一层壳。全长地板（座椅平台顶面 = `groundAt`）、两侧"锈蚀外壳 + 洁净内衬"叠合墙、分段压低/倾斜顶棚（`SR_CEIL` + `srCeilUnder/srCeilYAt` 作为顶棚高度唯一来源，最低可走 2.15m，`ceilingRaw` 与跳跃头顶判定同源）、真实窗洞与窗框、整排向驾驶端同向偏斜的扶手与吊环（`railAt(z)` 统一求高，吊杆真实接到顶棚）、两侧座椅与落地支架、车端隔断与贯通道门框。墙板与座椅不自发光，只有灯带自发光；灯池固定 8 盏，三态靠 `applyCarState()` 一个入口互斥切换车体 visible 与灯强度、碰撞动静。
- 检查完成条件改为"真实进车 + 顺车长看过去"：`carInspected` 需玩家在车厢内部（`inside` 判定）且视线沿车长（`|dir.z|>0.55`），在车外贴窗不再算完成；`state.maint.windowSeen` 仅作旧名兼容。
- 上一版"窗后 0.41m 浅腔"已整体删除（用户否决：白侧片会穿露到车外，且不构成整车异变）。
- 外部一致性（同日小修）：前后外端面按"车体全宽锈层 + 内衬"分层收口；六片门叶用逐面材质（朝车内整洁内饰、外面与四边旧漆）；顶棚板改 `roofBox()` 六面材质（仅朝下车内面是内饰，顶面/端头/侧收边一律旧漆），消除车外可见的浅白新盖边。
